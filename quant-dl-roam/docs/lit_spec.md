## 1. StockMixer reproduction spec (paper + official code)

### 1.1 Input features and preprocessing
- Task: given panel `X ∈ R^{N×T×F}` predict next-day close `p_t`, report return `r_t = (p_t − p_{t−1})/p_{t−1}` (SM p.3, Eq.1). Output = one scalar per stock.
- **N** = #stocks in the universe (NASDAQ 1026, NYSE 1737, S&P500 474 — Table 1). Full universe must be in one "batch" (stock mixing couples all N; see 1.3).
- **T = 16** trading days ("all samples are generated by moving a 16-day lookback window along trading days", SM p.5; code `lookback_length = 16`).
- **F = 5** indicators per day. Paper only hints ("stock open price, close price or 5-day average close price", SM p.3); RSR README states the raw fields: open, high, low, close, volume. Code: `fea_num = 5`; `eod_data = single_EOD[:, 1:]` (drops the date column) and `price_data = single_EOD[:, -1]` (last CSV column is the close used as `base_price`). **Exact column order of the 5 fields is UNKNOWN** (not documented in repo/README); assumption: OHLCV, close as the price column (see deviations).
- Label/GT: `gt[t] = (close[t] − close[t−1]) / close[t−1]`, `steps = 1` (code `load_data.py`, `train.py`).
- **Normalization: paper says "normalized stock historic patterns" (SM p.3) but the released training code contains NO per-feature normalization** — raw values go into `Conv1d`/linear layers; the only normalization is `LayerNorm` inside mixing blocks. Whether the released `.pkl` inputs were pre-normalized is **UNKNOWN** (could not download the 25 MB `dataset/NASDAQ/eod_data.pkl`; shell network is blocked). We must decide our own normalization (see deviations).
- Missing data: sentinel `-1234` → feature replaced by `1.1`, per-day mask = 0 (`np.min` of 16-day window mask); NASDAQ drops the last day ("lots of missing data"). Loss/eval are masked.
- S&P500 branch: `data = np.load('SP500.npy')[:, 915:, :]`, all-ones mask, gt and base price from `data[:,:,-1]`.

### 1.2 Architecture (three mixing modules — exact numbers from `src/model.py`)
Notation: input `(N, T=16, F=5)`; `m` = market dim; all GELU unless stated.
- **Pre-branch**: `Conv1d(in=F=5, out=5, k=2, s=2)` over time → `(N, 8, 5)`; this is the "scale" stream `y`.
- **Multi-scale time mixing** (`MultTime2dMixer(time_step=16, channel=5, scale_dim=8)`):
  - Main branch `Mixer2dTriU(16,5)`: `LN[16,5]` → transpose → **TriU causal time mixer** → transpose → `LN(x + input)` → **channel/indicator mixer** `MixerBlock(5,5)` → residual `x + y`. Output `(N,16,5)`.
  - Scale branch `Mixer2dTriU(8,5)` on the conv stream: same structure with `T'=8`. Output `(N,8,5)`.
  - Concat on time axis: `[input(16) , main(16) , scale(8)]` → **`(N, 40, 5)`**, i.e. effective `d = 40`.
  - Paper's version differs: patches via `Avgpool` with `k ∈ {T/2,T/4,1} = {8,4,1}`, i.e. `d = T + T/2 + T/4 = 28`, then one `FC` (SM p.4, Eq.5–7); paper says "for length 16, k ∈ {1,2,4}". Code implements the multi-scale branch as a single stride-2 conv + a 2nd TriU mixer, not avgpool k=4. **Report both; official code = 40.**
- **TriU causal time mixing** (`TriU(T)`): `T` linear layers; output position `t` = `Linear(t+1 → 1)` over `x[0..t]` (upper-triangular / causal mask, each step sees only itself and the past), then activation, then a second identical `TriU`. Activations: `GELU` in main branch, `Hardswish` in the scale branch (`nn.Hardswish`).
- **Indicator mixing** (`MixerBlock(C,C)`): `Linear(C→C)` → `GELU` (`acv = nn.GELU()`) → `Linear(C→C)`, wrapped by a pre-LN residual. `C=F=5`, hidden=5; dropout 0. Note: paper Eq.3 puts indicator mixing *before* time mixing; code applies channel mixing *after* time mixing inside `Mixer2dTriU`.
- **Stock mixing** (`NoGraphMixer(stocks=N, hidden_dim=m)`): `LayerNorm` over the stock axis → `Linear(N→m)` → `Hardswish` → `Linear(m→N)`; no residual in code (paper Eq.8 writes `Ĥ = H + M2 σ(M1 LN(H))`; discrepancy). `m` = **20 (NASDAQ), 25 (NYSE), 8 (S&P500)** (paper p.5; code default `market_num = 20`). Only **1** stock-mixing block.
- **Head**: `channel_fc = Linear(F=5 → 1)` applied to the `(N,40,5)` tensor → `(N,40)`; then two independent heads `Linear(40→1)`, one on the pre-stock stream and one on the stock-mixed stream, **summed** (`ŷ = time_fc(y) + time_fc_(z)`). Paper describes concat+FC; algebraically equivalent to a single linear layer on the concatenation.
- Model size: paper reports params/memory second only to RNN (~186K for NASDAQ — paper figure discussion; treat as approximate, not a quoted constant). Not needed for reproduction.
- Batch/LayerNorm details: no dropout, no dropout by default; GELU despite paper's ablation saying ReLU/HardSwish > GELU (see deviations).

### 1.3 Loss, optimizer, schedule (code; paper gives only lr and α)
- **Loss** (`get_loss`): `L = MSE(rr·mask, gt·mask) + α · mean(ReLU(pre_pw_dif · gt_pw_dif · mask_pw))`, where `rr = (pred − base_price)/base_price` (predicted return), and pairwise-ranking terms are `pre_pw_dif[i,j] = rr_i − rr_j`, `gt_pw_dif[i,j] = gt_j − gt_i`, `mask_pw = mask·maskᵀ`. Masked entries zeroed.
- **α = 0.1** (paper p.5; code `alpha = 0.1`).
- **Optimizer = Adam, lr = 1e-3** (paper: "learning rate is 1e−3"; code `torch.optim.Adam`, `lr=0.001`).
- **Epochs = 100** (code only; paper UNKNOWN). No early stopping; the epoch with **lowest validation loss** is kept and its test metrics reported.
- **Batch = 1 trading day (all N stocks)** — code iterates one offset at a time over 740 shuffled offsets/epoch; paper does not state a batch size (UNKNOWN). Because stock mixing is over the whole universe, stocks **cannot** be split across batches.
- Seeds: `np.random.seed(123456789)`, `torch.manual_seed(12345678)`; 3 runs averaged in paper.
- Runtime/GPU: RTX 2080 Ti 12 GB (paper p.5).

### 1.4 Split protocol and metrics
- Chronological split by trading-day **offsets** (not by date): NASDAQ/NYSE `valid_index = 756`, `test_index = 1008`; train windows = offsets `0 … 739`, val = `756 … 1007`, test = `1008 … end`. Note the 16-day lookback+1 step means the first train window needs `offset+16+1 ≤ 756`, and offsets 740–755 are unused (boundary). Paper Table 1: **train 756 / val 252 / test 273** days for NASDAQ & NYSE; **S&P500 1006 / 253 / 352**.
- Metrics (paper p.5 + `src/evaluator.py`): **IC** (mean daily Pearson corr), **"RIC"**, **prec@N** (paper; code reports `prec_10`: fraction of top-10 predicted stocks with gt ≥ 0), **Sharpe Ratio** (paper; code `sharpe5 = mean/std of top-5 equal-weight daily returns × √252`, 15.87). ⚠ Code's `RIC` is `mean(IC)/std(IC)` = **ICIR, not Spearman rank IC** as the paper claims — reproduce both and label separately.
- Code also reports MSE.
- Reference numbers to beat/validate (paper Table 2): NASDAQ StockMixer IC **0.043**, RIC **0.501**, prec@N **0.545**, SR **1.465**; NYSE 0.029 / 0.351 / 0.539 / 1.454; S&P500 0.041 / 0.262 / 0.551 / 1.586.

## 3. MASTER market-guided gating mechanism (for a gated recurrent variant)
- Setup: `x_{u,t} ∈ R^{F}` per stock `u`, `t ∈ [1,τ]`; **τ = 8**, prediction interval **d = 5**; **F = 158** (Alpha158 features, Qlib) for CSI300/CSI800 (paper §Experiments).
- **Market status vector `m_τ`, dimension `F' = 63`**: built from **CSI300, CSI500 and CSI800** index series, with referable intervals **d' ∈ {5,10,20,30,60}**. Paper text defines the contents per index as: current market-index price at `τ`, plus **average and standard deviation of index price** over the past `d'` days, plus **average and standard deviation of index trading volume** over the past `d'` days. Count check: 3 indices × (1 current price + 5 windows × (price avg, price std, volume avg, volume std)) = 3 × 21 = **63** (count is stated in paper; the exact per-feature decomposition is inferred — the paper does not print the formula).
- **Gate**: one linear layer + softmax over the feature dimension, rescaled by `F`:
  `α(m_τ) = F · softmax_β( W_α m_τ + b_α )`, with `W_α ∈ R^{F×F'} = R^{158×63}`, `b_α ∈ R^{F}=R^{158}`, `α(m_τ) ∈ R^{158}`.
  `β` = temperature: **β = 5 (CSI300), β = 2 (CSI800)**; smaller β ⇒ sharper/stronger feature selection, larger β ⇒ gate≈uniform (gating off).
- **Application (Hadamard, shared across stocks and time within a day)**: `x̃_{u,t} = α(m_τ) ⊙ x_{u,t}` for all `u ∈ S`, `t ∈ [1,τ]`. The `F`-multiplier compares the softmax distribution with uniform `1/F`, so coefficients >1 amplify and <1 suppress a feature; this is a market-state-conditioned **feature-selection/scaling** gate, not a hidden-state gate.
- Downstream (context for a recurrent variant): `y_{u,t} = W x̃_{u,t} + b` (single linear → **D = 256**) + fixed sinusoidal PE → 1-layer transformer encoder intra-stock (**N1 = 4 heads**, FFN 2-layer ReLU+residual) → per-time-step inter-stock MHA (**N2 = 2 heads**) → temporal aggregation (last step as query) → FC.
- Training: **D = 256, lr = 1e-5, ≤40 epochs with early stopping, 5 seeds**; label = `d`-day return, **daily cross-sectional Z-score normalized** (`NormS`); split 2008–2020Q1 train / 2020Q2 val / 2020Q3–2022Q4 test; metrics IC, RankIC, ICIR, RankICIR, top-30 AR & IR.

## 4. HIST data requirements (concept-oriented graph)
- **Stock features**: Qlib **Alpha360** = 60-day lookback × **6 daily fields** → **360-dim** vector per stock per date. Fields: opening price, closing price, highest price, lowest price, **VWAP**, trading volume. Label = next-day close-to-close return `d_t = (P_{t+1}−P_t)/P_t`, normalized **across stocks on the same date**. Universe CSI100/CSI300; time split 2007–2014 train / 2015–2016 val / 2017–2020 test.
- **Predefined concept data (the extra requirement)**: a **stock→concept membership** for `m` concepts `T_j` (industry + main business, scraped from Tushare), which may change over time; average **410 concepts/day (CSI100)** and **1344 (CSI300)**. From it: a **stock-concept bipartite graph**; each concept gets a learned embedding by aggregating its member stocks (LeakyReLU FFN); concept embeddings are then **corrected** by cosine-similarity softmax over *all* stocks (`α^{t,1}_{ki} = softmax_j(cos(x_i, e_k))`), so stocks not formally linked can still contribute (handles missing/irrelevant memberships); aggregates are fed back to stocks. All module outputs are combined via a **doubly residual** (backcast/forecast) design.
- **Hidden concepts**: **no external data needed** — `n` hidden concepts initialized from the `n` stock embeddings, connect each stock to its most-similar hidden concept (cosine, excluding its own), aggregate, LeakyReLU. Purely computed from stock embeddings each date.
- **One-sentence architecture**: 2-layer GRU stock encoder (last hidden state = stock embedding) → predefined-concept bipartite-graph module → hidden-concept module (dynamic cosine graph) → individual-information module → FC prediction, chained by a doubly-residual design.
- **Minimum requirements / fallback if we have no concept membership**: (a) run the **hidden-concept + individual modules only** — ablation shows IC 0.097 (CSI100) / 0.110 (CSI300), *better* than predefined-concept-only 0.087/0.101; (b) or substitute sector/industry membership (e.g. GICS / 申万一级) as the predefined concepts — HIST itself only needs a binary stock×concept matrix, no graph weights or edge features; (c) the remaining hard requirement is just a **per-stock daily OHLCV(+VWAP) panel with a 60-day history window**.

## 5. Deviations we may need
1. **Universe/panel**: StockMixer needs a **fixed stock set N** (stock mixing is `Linear(N↔m)` over the whole cross-section, one day per batch). If our data is a survivorship-free panel with changing membership, we must fix a universe per run (or add masking/embedding for absent stocks) — otherwise dimensions break. This is the single biggest implementation risk.
2. **Features**: we likely have OHLCV, not RSR's exact columns; paper says "normalized" but code does not normalize. Start from **F=5 raw OHLCV**, and if training diverges, try (i) per-stock rolling z-score of each feature over the lookback window, (ii) price ratios `p_t/p_{t-1}` for OHLC, (iii) keep raw + rely on internal LayerNorm (code behavior). Log which was used; do not silently mix.
3. **Missing data**: no `-1234` sentinel in our data; must build a per-day mask, fill gaps (e.g. forward-fill then mask the loss), and ensure the 16-day window is fully valid or masked. NASDAQ-specific "drop last day" hack is not needed.
4. **Metric definition**: code's `RIC` is ICIR, paper calls it rank IC. Report **IC, RankIC (Spearman), ICIR, prec@10, long-short/top-5 Sharpe** explicitly so numbers are comparable to both.
5. **Time-mixing variant**: paper `d=28`, avgpool patches `k∈{1,2,4}`; code `d=40`, stride-2 conv + 8 dims. Implement the **code version** first (official), and log the paper variant as an ablation if cheap. TriU causal mask is the essential idea (keep it).
6. **Stock mixing residual**: paper Eq.8 has `H + ...`, code omits the residual. Try code version first; add residual as an ablation (1 line).
7. **Activation**: paper's ablation says **ReLU/HardSwish beat GELU**; code ships GELU. Use **HardSwish** (or ReLU) and record it.
8. **No concept membership (HIST)**: use hidden-concept-only variant (ablation-supported) or industry baseline; do **not** claim reproduction of HIST's predefined-concept results. If we later get 申万/中信 industry or concept tags, only a **binary stock×concept matrix per date** is needed (plus optional time-varying versions) — that is the entire HIST data contract.
9. **Market gating (MASTER)**: for our market we need an index series (e.g. CSI300 or our own cap-weighted index) to build `m_τ`; `F' = 63` is tied to 3 indices × 5 windows, so with 1 index `F' = 21` (1 + 5×4). `F` becomes our feature count (not 158). Keep `F · softmax_β(W m + b)`, β as the tuning knob, gate applied per day to all stocks/time steps.
10. **Compute**: 100 epochs × ~740 steps × N=1026 forward/backward may be heavy on CPU; paper used a 2080 Ti. Consider fewer epochs only as an explicit deviation (then do not claim paper numbers).
11. **Data leakage**: split strictly by date offsets; MASTER/HIST normalize labels **cross-sectionally per day** (not over time) — do the same; never fit scalers on the full series before splitting.

Unknowns explicitly marked: exact 5-feature column order in RSR pkl; whether released pkl inputs are pre-normalized; paper's batch size and epoch count; MASTER market-vector exact per-feature formula (count 63 is stated); StockMixer parameter count.
