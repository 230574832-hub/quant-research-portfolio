# 数据缺陷通告 D1：源面板混入 271 个法定休市日，导致标签错位与 43% 的窗口失效

**发现时间**：2026-11-15
**发现方式**：构建深度学习横截面基准时，发现「测试期 521 个交易日里只有 298 天有有效样本」且每日有效股票数呈极端双峰（中位数 449 只 / 25 分位 0 只），追查后发现 **16 日回看窗口内存在个别交易日，全市场 500 只股票的特征同时为 NaN**——一天即可废掉整个横截面的窗口。
**结论**：不是模型问题，是**日期轴缺陷**。源行情库 `daily_panel_v12.sqlite` 按**日历日**给行，法定休市日的价格是前一交易日的结转值（有值），但 `volume`/`amount` 为 0。这些日期根本不是交易日，却被当成交易日参与样本构造。

---

## 1. 证据链

### 1.1 休市日的市场状态

| 日期 | 星期 | 面板有限股票数 | `volume>0` 的股票数 | 落入 base 池 |
|---|---|---:|---:|---:|
| 2011-09-12 | 周一 | 1928 | **0** | 0 |
| 2012-01-25 | 周三 | 1999 | **0** | 0 |
| 2012-10-03 | 周三 | 2155 | **0** | 0 |
| 2013-02-13 | 周三 | 2169 | **0** | 0 |
| 2012-01-04 | 周三 | 1991 | 1940 | 796 |
| 2011-09-13 | 周二 | 1929 | 1876 | 1199 |

价格序列有值（结转），成交量为 0；对照相邻的正常交易日则一切正常。

### 1.2 失效日期与 A 股法定节假日完全对齐

全市场 `base` 股票数为 0 的日期共 **386 天**，剔除面板起始的 119 天预热期（`MIN_LISTED=120` 日上市要求）后剩余 **271 天**，逐段比对：

| 失效区间 | 对应节假日 |
|---|---|
| 2011-10-03 .. 10-07 | 国庆 |
| 2012-01-02 .. 01-03 | 元旦 |
| 2012-01-23 .. 01-27 | 春节 |
| 2012-04-02 .. 04-04 | 清明 |
| 2012-04-30 .. 05-01 | 劳动节 |
| 2012-06-22 | 端午 |
| 2012-10-01 .. 10-05 | 国庆 |
| 2013-01-01 .. 01-03 | 元旦 |
| 2013-02-11 .. 02-15 | 春节 |
| 2013-04-04 .. 04-05 | 清明 |

（完整 37 个区间见 `logs/build_dataset4.log` 与 `out/` 重建产物。）

### 1.3 三重传导

1. **窗口整体失效**：`traded = (V>0) & (M>0)` 在休市日对全市场为假 → 当日 `Fz` 全 NaN → **任何跨越休市日的 16 日回看窗口对全部 500 只股票失效**。休市日成簇出现（3–5 天一段），一个 16 日窗口命中至少一段的概率约 43%，与实测的「测试期 43% 的日期有效样本 < 20 只」吻合。
2. **标签错位**：休市日 `adjclose` 为结转值，故 `y1[t] = adjclose[t+1]/adjclose[t] − 1` 在**节前最后一个交易日恒等于 0**（伪零收益），真实的多日收益被推迟到节后首日才体现。标签与收益实现错开一天。
3. **市场状态被污染**：`MS` 的 5 日/20 日市场收益、20 日波动率把这些伪零收益当成真实观测。

## 2. 根因

`quant-lab/src/build_panel.py` 的 `dates = w["close"].index`，即源库 `daily_panel_v12.sqlite` 中出现过的全部日期。源库按日历日铺行，休市日保留行但成交量为 0。

`quant-lab` 的面板已封存（tag `v5.1-frozen-2026-11-14`），**本次修复不改动上游资产**，而是在 `quant-dl-roam/src/build_dataset.py` 载入后即刻按同一规则裁剪日期轴：

```python
mkt_turnover = np.nansum(np.where(np.isfinite(V), V, 0.0), axis=1)
trade_day = mkt_turnover > 0
```

`src/evaluate_wf.py` 的 `load_panel()` 采用**完全相同**的过滤规则，保证预测文件里的 `date_idx` 与面板数组 1:1 对齐。

| 折 0 测试期有效天数 | 298 / 521 | **488 / 488** |
| 折 0 训练期有效天数 | 512 | **847** |
| 折 0 测试样本行数 | 135,901 | **221,623** |

修复后标签的「极端跳空日」也回到了真实事件：

| 日期 | 市场均值收益 | 事件 |
|---|---:|---|
| 2025-04-07 | **−12.23%** | 关税冲击 |

| 2020-02-03 | −8.97% | 春节后首个交易日 |

这些收益此前被拆成「节前 0% + 节后 X%」两段。

## 4. 连带修复的 off-by-one

同一批排查中修正了紧凑样本 `dataset_top800.npz` 的涨停标记越界：

```python
# 修正前
bb = blocked_buy[row_date + 1, row_code]   # 实际取到的是 t+2 开盘涨停
# 修正后（blocked_buy[t] 的定义即"t+1 开盘涨停"）
bb = blocked_buy[row_date, row_code]
```

`features.npz` 中按 `(日期, 股票)` 保存的 `blocked_buy` 语义未变，评估脚本另行从原始面板自行计算涨停判定，不依赖该数组。

## 5. 处置

1. 休市日从日期轴剔除，**数据集整体重建**（`logs/build_dataset4.log`），旧产物作废；
2. `src/evaluate_wf.py` 同步采用同一交易日轴；
3. **此前在缺陷数据上产出的全部训练/评估结果作废**，已在缺陷修复后重跑 3 个随机种子 × 5 折的完整网格；
4. 该缺陷不影响 `quant-lab` 已封存的 V5.1 基线——V5.1 的面板与该缺陷的传导路径不同（其股票池与执行引擎不做 16 日窗口有效性判定），但建议在 V5.2 中一并裁剪日期轴以对齐口径。
